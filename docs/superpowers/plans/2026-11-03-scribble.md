# Scribble Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Palm users sketch 160x120 black and white notes and send them to other users through an invite-only FastAPI server that also has a React web viewer.

**Architecture:** One FastAPI app holds all business rules in plain functions over a `sqlite3` connection (`accounts.py`, `notes.py`). Two thin HTTP surfaces call them: a plain-text Palm API at `/palm/v1` and a JSON web API at `/api`. The Palm app keeps its portable logic (sketch buffer, protocol parsing) in host-testable C files and its device code in a separate file, as `htmlclean` does.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, argon2-cffi, Pillow, pytest, httpx; React + Vite + TypeScript + Vitest; SQLite; Docker; systemd; nginx. Palm: C89 with the existing Docker toolchain and fujinet-lib-palmos.

**Spec:** `docs/superpowers/specs/2026-11-03-scribble-design.md`

## Global Constraints

- Note bitmap: 160x120, 1 bit per pixel, 20 bytes per row, 2400 bytes, MSB first, 1 = black.
- Handles: `^[a-z0-9_]{3,16}$`, unique, immutable. Input handles are lower-cased before checks.
- At most 10 recipients per note; at most 30 notes sent per account per rolling hour; sender may not be a recipient; no duplicate recipients.
- Every account needs a single-use invite code (optional expiry). No open sign-up.
- A recipient never learns who else received a note. A sender sees all recipients.
- Device tokens and sessions: random, stored only as SHA-256 hashes. Passwords: argon2. Failed logins rate limited.
- Palm API: HTTPS only in deployment, versioned under `/palm/v1`, plain text, errors are a first line `err <short reason>`; auth header `Authorization: Bearer <token>`.
- Palm code: C89, no floating point, Palm OS 3.x, every app calls `fuji_palmos_close()` on exit, headers included in the order described in `palm/apps/common/fnapp.h`.
- Deployment: one Docker image, a systemd unit that runs it, nginx in front; SQLite on a mounted volume.

## Review Focus

1. A send with an unknown, duplicate, own, or 11th handle is rejected as a whole and stores nothing.
2. A user fetching, deleting, or marking read a note they are neither sender nor recipient of gets the same error as a nonexistent id.
3. A send body of the wrong size (0, 2399, 2401 bytes, or no newline after the handle line) is rejected and stores nothing.
4. A disabled account or revoked token is refused on its very next request, on both surfaces.
5. A directory prefix containing `%`, `_`, or uppercase letters neither acts as a wildcard nor errors; the result matches the lower-cased literal prefix.

## Task 5: Palm API

**Files:** Create `server/app/{palm_api,main}.py`, `server/tests/test_palm_api.py`; extend `conftest.py` with `client` (FastAPI `TestClient` over a temp DB via `create_app(Settings(...))`) and helpers `make_user(handle) -> (id, token)`.

**Interfaces:**

- Wire format (all responses `text/plain`; always HTTP 200 except a missing/bad token is 401 with body `err auth`):
  - `POST /palm/v1/login`, body `username\npassword\n` → `ok\n<token>\n<handle>\n`.
  - `GET /palm/v1/inbox?offset=0&limit=20` → `ok\n` then one line per note `id|unix|sender|unread` (`unread` is `1` or `0`).
  - `GET /palm/v1/sent?offset=0&limit=20` → `ok\n` then `id|unix|h1,h2,...`.
  - `GET /palm/v1/directory?prefix=&offset=0&limit=50` → `ok\n` then one handle per line.
  - `GET /palm/v1/notes/{id}` → exactly 2400 raw bytes (`application/octet-stream`), or `err no such note\n`. Marks read for a recipient.
  - `POST /palm/v1/send`, body `h1,h2\n` + 2400 bytes → `ok\n<id>\n`.
  - `DELETE /palm/v1/notes/{id}` → `ok\n`.
  - Any `ServiceError` → `err <reason>\n`.
